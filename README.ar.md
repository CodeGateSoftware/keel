# كيل (keel)

**العربية** | [English](README.md)

**كيل محرّكُ امتثالٍ شرعيٍّ قابلٌ للتدقيق، لتداول العملات المشفّرة الفوري (Spot)** —
سككُ أمانٍ حتميّةٌ لا يمكن تجاوزها، وفرزُ أصولٍ موثَّقٌ يرفض عند غياب الدليل،
وتقنينُ القبض الحُكميّ (§65.4) فحصًا قابلًا للتنفيذ — وفوق ذلك كلّه وكيلُ تداولٍ
آليٌّ مرجعيٌّ لمنصّة Coinbase. كثيرون لديهم بوتُ تداول؛ لكن لا أحد تقريبًا يملك
هذه الآليّات الامتثالية، وهي الجزء الذي يستحقّ القراءة.

**النتيجة الصادقة، نقولها نحن أوّلًا:** لا توجد عائلة قواعدٍ مُصدَّرة تحقّق ربحًا
صافيًا عند رسوم الآخذ (taker) المدفوعةِ فعليًا على هذه المنصّة — فالتكلفة هي القيد
الحاكم، وتقاطُعُ المعاملات والرسوم الممكنِ فارغٌ تحت تنفيذٍ مطابقٍ للإنتاج
([سجلّ التجربة](docs/experiments/2026-08-13-restated-under-a-production-faithful-engine.md)).
الغاية من هذا المشروع هي آليّاتُ الإنفاذ والقياسُ الصادقُ لما يمرّ عبرها، لا
ادّعاءُ تفوّقٍ في الأداء. الزائر الذي يكتشف ذلك بنفسه يشعر بالخداع؛ أمّا من
نُبِّه مسبقًا فيقرؤه أمانةً ودقّةً.

> **كيل ليس محرّكَ فتاوى؛ إنه محرّكُ إنفاذٍ لحكمٍ شرعيٍّ أنت من يزوّده.** كيل لا
> يستنبط تصنيفًا شرعيًّا من بيانات السوق أبدًا. أنت تسجّل التصنيف — بمصدرٍ واسمٍ
> منسوبٍ إليه (`keel assets attest`) — وكيل ينفّذه حتميًا، رافضًا كلَّ ما ليس
> موثَّقًا. الحُكمُ يسكن توثيقك لا الشيفرة، ولذلك يحصل مُشغّلان يتبعان مذهبين
> مختلفين على إجابتين مختلفتين من الشيفرة نفسها، بتصميمٍ مقصود. انظر
> `CONTRIBUTING.md` لمعرفة ما يعنيه ذلك لطلبات الدمج.
>
> *(بالإنجليزية: "keel is not a fatwa engine. It is an enforcement engine for a ruling
> you supply.")*

**لم تَجرِ أيُّ مراجعةٍ علميةٍ شرعيةٍ للأساس الفقهيّ لكيل.** الأساسُ قراءةٌ موثَّقةُ
المصادر لمُشغّلٍ واحد — نُشرت في [`docs/fiqh-basis.md`](docs/fiqh-basis.md) تحديدًا
ليُمكن تدقيقها والاعتراض عليها — وكلُّ مُشغّلٍ مسؤولٌ عن توثيقاته الخاصّة.

كيل أداةٌ شخصية، ليست نصيحةً مالية وليست فتوى ولا نصيحةً شرعية — انظر التنبيهات في
أسفل هذه الصفحة.

## جرّبه في خمس دقائق

كلُّ ما هنا للقراءة فقط ومن جهة التداول الافتراضي (paper): لا أموال، ولا شيء في هذا
المسار يمكنه تقديم أمر شراء. مُتحقَّقٌ منه على نسخةٍ نظيفة من المستودع. تحتاج
[uv](https://docs.astral.sh/uv/) و**مفتاح Coinbase Developer Platform (CDP) مجانيًّا
للقراءة فقط** — تُجلَب بيانات الشموع عبر العميل المُصادَق، لذا يفشل الأمر
`keel fetch` من دون مفتاحٍ بخطأ `AuthenticationError`؛ نقولها مقدَّمًا كي لا تكون
مفاجأةً في الخطوة الرابعة.

```bash
git clone https://github.com/CodeGateSoftware/keel.git && cd keel
uv sync --all-extras --dev        # أي Python من 3.11 فما فوق (المستودع يُطوَّر على 3.14)
cp .env.example .env              # ضع مفتاح وسرّ CDP فيه — لبيانات السوق فقط
uv run keel rules seed            # سجّل عائلات القواعد كمرشّحات
uv run keel fetch                 # اجلب تاريخ الشموع للقائمة المسموحة الافتراضية
uv run keel simulate --years 1 --skip-within-cap
```

يعيد الأمر `keel simulate` تشغيل القواعد الحقيقية حتميًّا فوق التاريخ المجلوب،
ويقارنها بمقياس DCA، ويكتب تقرير GO-LIVE أو TRAIN-MORE مع البوابات وأرقامها. على
القواعد الافتراضية سيخبرك على الأرجح **TRAIN MORE** ويسمّي البوابات التي لم تُجَز —
فهذا هو المحرّك يعمل، لا يتعطّل؛ الأمانةُ هي الميزة. الخطوات التالية — ترقية قاعدة
عبر البوابة (`keel rules promote`، التي ترفض الترقية من دون فحص فرطِ مواءمة)، وتشغيل
الوكيل الافتراضي (`keel agent`، فالوضع الافتراضي هو paper)، ثم أوّل أمرٍ حقيقيٍّ
تحت إشرافك — كلّها في [`docs/go-live-runbook.md`](docs/go-live-runbook.md) (بالإنجليزية).

## نطاق هذه الصفحة

هذه الصفحة نقطةُ دخولٍ عربية: ما هو كيل، ونتيجتُه المقيسة، وحدودُه، وكيف تجرّبه.
الوثائق الكاملة — سجلّات التجارب، وكُتب التشغيل، وأساسُ الفقه (`docs/fiqh-basis.md`)،
ودليلُ المساهمة (`CONTRIBUTING.md`) — **بالإنجليزية** وتبقى كذلك؛ هذه الصفحة ليست
وعدًا بترجمة كل شيء، بل بابٌ تدخل منه. صيغت المصطلحات وفق الاستعمال الشرعيّ
المستقرّ أعلاه، وإن رأيت تحسينًا في صياغةٍ أو مصطلحٍ فأهلًا بك في
[Discussions](https://github.com/CodeGateSoftware/keel/discussions) — تصحيحُ اللغة
والاصطلاح فيها مرحَّبٌ دائمًا.
